## 0. Verdict

**Winner of agent-RSS v3: `anv` (benchmark default `--no-mind`).** It is the
lowest-memory harness on
every one of the ten task classes — **25 MB median own-process peak, 21 MB
floor, 0 MB auxiliary** — against `jcode` 45 (runner-up, and the leanest
zero-config option), `codex` 98, `aider` 246, `claude` 431, `opencode` 582. It
is also the fastest median wall time (15.4 s vs 19.3–78.9 s) and it verified
**37/37** with zero context-timeouts.

**`--no-mind` is anvaya's benchmark default.** The Mind — an experiential
learning store whose daemon runs an ONNX embedding pipeline at request time —
is explicitly out of scope for v3: it is young and not yet optimised, so
measuring it as a harness cost would price the feature, not the agent loop.
With the Mind on, anv is the *largest* tree measured (~213 MB, ~170 MB of it
ORT session/arenas; v2 §3.1). The Mind-on configuration is deferred to a
future Mind-optimisation round and is never ranked against a pure harness here.

The declaration carries two further conditions, stated so the result cannot be
over-read:

1. **Pre-release build.** The `--no-mind` switch is not in anv's current
   public release; v3 numbers come from a pre-release build (fingerprint
   `42542492c9d0a058`). They will be re-run on the shipping binary.
2. **Scope.** n=1 per cell; wall time is model-latency dominated; `copilot` is
   untested; and `aider`/`claude`/`opencode` lose RSS partly to their language
   runtimes, which is a fact about their execution cost, not their engineering.

Execution-rate co-leaders with a perfect sheet: `anv` 49/49, `opencode` 48/48,
`jcode` 44/44, `codex` 17/17. `claude` 32/34 and `aider` 38/46 — aider's misses
are its missing filesystem-search capability plus one clarification deferral,
`claude`'s are two intermittent context aborts on the most invasive read task
at a 128 K window (§6).

## 2. Bottom line

1. **`anv --no-mind` is the lowest-memory harness measured, on every task
   class: 21 MB floor, 25 MB median own-process peak** — below `jcode` (43
   floor / 45 median) and an order of magnitude below `opencode` (537/582).
2. **The ranking is a runtime result as much as a harness result.** The order
   `anv` < `jcode` < `codex` < `aider` < `claude` < `opencode` tracks
   native-Rust < native-Rust < native-Rust < Python < Node < Node.
3. **Execution rate:** 228/238 verified. The ten misses are 8 `aider` cells
   (7 from the missing filesystem-search tool — `wide_read`, `aggregate_scan`,
   one model-specific `build_pkg` — plus one clarification deferral on
   `edit_tool`) and 2 `claude × qwen pressure_read` aborts that reproduce
   intermittently (2 of 4 attempts) rather than deterministically (§6). No
   harness lost a run to a timeout.
4. **`jcode` remains the leanest zero-config harness** (43–50 MB flat, zero
   auxiliary processes, no daemon).
5. **`anv` is measured in its benchmark default mode, `--no-mind`** — the Mind
   is a young, unoptimised retrieval subsystem (an ONNX embedding pipeline at
   request time; v2 measured ~190 MB), deliberately deferred to
   a Mind-optimisation round rather than ranked as harness overhead.

## 6. Integrity, failures, and what n=3 changed

**228/238 verified, 0 timeouts, 0 idle-kills.** The ten misses are 8 `aider`
cells and 2 `claude` aborts. The two heaviest classes (`pressure_read`,
`edit_tool`) were then replicated at n=3 across every harness/model pair to
separate incidents from behaviours:

- **`claude × qwen pressure_read` — intermittent, 2 of 4 attempts.** Both
  aborted attempts exited rc=1 (843 s and 546 s) with Claude Code's own guard:
  *"compact within 3 turns of the previous compact, 3 times in a row. A file
  being read or a tool output is likely too large for the context window."* The
  other two attempts passed (628 s, 85 s). At a 131 072-token cap the four
  ~350 KB briefs (~90 K tokens each) sit at the edge of the window, so the
  abort is a coin-flip rather than a deterministic ceiling. On
  `deepseek-v4.1-flash` (1 M) all attempts pass.
- **`opencode × qwen pressure_read` — one transient in four attempts**, and
  that attempt *verified*: the correct answer was written before the non-zero
  exit. Three follow-ups exited cleanly; recorded as verified with
  `clean_exit=false` and not treated as a pattern.
- **`codex × qwen edit_tool` — the +214% spike was a one-off.** One serial
  anchor run peaked at 291 MB (2.1× its floor); three campaign follow-ups
  landed at 92–146 MB. The cell is not reproducibly memory-hungry.

### The aider execution-model finding

Eight unverified `aider` cells, one family: **aider behaves like an edit
assistant, not an autonomous agent.** Seven are the missing filesystem search
or traversal tool. Given a needle-in-200-files task it reads the repo-map
summary, then answers:

> *"I need to read the contents of the modules under `src/` … Could you add
> the source files to the chat so I can inspect their contents?"*

For `aggregate_scan` it did the work in the wrong place: it wrote and applied a
`compute_sum.py` script, then told the user to run it — and never produced
`answer.txt`. The eighth is the same behaviour in a different coat: on one
`edit_tool` trial it stopped to ask *"Which would you like? Tell me the real
test contents…"* instead of acting. This is not a bug in the benchmark or the
gateway; it is the difference between an edit assistant and an agentic harness,
and it is exactly the kind of thing an execution-rate column is for.

## 7. Method findings

### 7.1 anv's no-mind build is a provenance prerequisite, not an extra arm

The benchmark default is `--no-mind`, but that switch is not in anv's current
public release: `ANV_NO_MIND=1` is silently ignored there and a 190 MB
`mind-daemon` spawns regardless — verified by direct reproduction, not
inferred. v3 therefore measures a purpose-built pre-release binary
(fingerprint `42542492c9d0a058`). Until the mode ships, anv's numbers in this
study are **pre-release build numbers**, and any future campaign must re-check
that the mode actually took effect (process-tree aux and `.anvaya/mind/`
absence, §7.2), because the switch is invisible in `--version`.

### 7.2 Conformance checks used

No-mind was confirmed at the process level, not from the flag: no
`mind-daemon` process carrying the workspace path during or after the run, no
`.anvaya/mind/` directory created, `aux = 0.0` in every measurement record.

### 7.3 The parallel/serial question was answered, not assumed

Waves A/A2/B ran at jobs 4–6 with a free-memory gate; Wave C re-ran the floors
and one real task serially. Floor agreement between the two regimes is tight
(`anv` 21/21, `jcode` 43/43, `codex` 93/93, `aider` 242–245, `claude` ~390,
`opencode` 537–587 MB), so on a machine with >6 GB free the parallel records
did not visibly deflate. The serial anchor remains the quoted floor.

### 7.4 Two measurement artifacts were caught and fixed mid-campaign

- **Idle timeout vs model latency.** The first pass used a 300 s idle cap; qwen
  can spend longer than that before its first token on multi-hundred-KB reads.
  Three runs were killed (recorded as failures, kept in
  `records/archive/superseded-2026-09-16/`), the cap was raised to 900 s, and all three
  cells then passed. A run with no output for 15 minutes is a real result; five
  minutes is a tuning parameter.
- **Process-name matching.** A pinned benchmark binary
  (`anv-nomind-bench`) and Python entry points (`Python:aider`) are both
  invisible to a naive `basename == harness` test. The runner now matches the
  configured binary's basename and either side of a colon label, and the report
  helper was fixed to match.

### 7.5 Multi-turn continuation, per harness

`long_session` (6 turns: a turn-1 codename plus three fact values that must
survive to a turn-6 synthesis) ran only on harnesses with a documented resume:
`anv --continue`, `claude -c`, `opencode run --continue`,
`codex exec resume --last`. jcode and aider were skipped with reason (jcode's
resume needs a session id its headless output does not surface; aider has no
headless resume). All 9 attempted continuations verified.

### 7.6 Gateways decide the matrix, not preference

| pairing | status |
|---|---|
| `claude` × opencode `glm-5.3-flash` | ✗ `/v1/messages` returns 500 (model is OpenAI-wire only) |
| `codex` × opencode (any) | ✗ needs Responses API + no way to set `x-opencode-session`; siemens-only |
| `aider` × opencode | ✓ via the runner's local pass-through, which injects `x-opencode-session` (aider/litellm cannot) |
| `claude` × both gateways | ✓ natively on the Anthropic Messages wire; siemens rejects Claude Code's default `effort=high`, so `--effort xhigh` (the gateway's own default) is pinned |

## 8. What this does and does not establish

**Established** (n=1 per cell, n=2–3 on floors): the harness-own-process
ranking on this corpus; anv `--no-mind` as the lowest and `jcode` as the
leanest zero-config; aider's search gap as a real execution-rate loss; the
model×harness wire matrix above.

**Not established:** statistical claims (n=1; ±6% session noise measured in v2
still applies); tokens/s for any harness except aider; cold/warm for jcode's
daemon; `copilot` (vendor-locked, still out of scope); task *quality* — all
verification is pass/fail assertions.

## 9. Next

1. **Ship the `--no-mind` mode in a public release** so the benchmark default
   is reproducible from a release build; re-run anv with `ANV_BIN` pointing at
   it. Until then v3's anv numbers are pre-release build numbers.
2. **Heavy-cell outliers are closed by n=3.** The codex spike was a one-off
   serial event (92–146 MB in follow-ups), claude's `pressure_read` abort is
   intermittent (2 of 4 attempts), and opencode's rc=1 was a single transient
   that still verified. What remains open for Phase 1 is the shipped
   `--no-mind` build and the Linux rerun.
3. Add `opencode:qwen3.8-flash` as a fourth model (it speaks both wires, so
   claude can use it; codex cannot — no Responses support).
4. Route `codex` onto opencode:deepseek through the same pass-through; its
   `/v1/responses` endpoint does work for that model.
